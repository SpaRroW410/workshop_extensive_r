Region 1 · Your First Script

RStudio projects, objects and types, factors, packages, reading and inspecting data

Briefing

Welcome to Region 1. No statistics yet: just the habits that make every later analysis work. Read first: Getting Started.

bp <- c(118, 126, 140, 132)      # a numeric vector
bp[2]                            # R counts from 1
[1] 126
sex <- factor(c("Male", "Female", "Female"))
levels(sex)                      # sorted alphabetically: the first is the reference
[1] "Female" "Male"

Objects and types. <- stores a value under a name. Numbers in quotes are text, and text cannot be averaged. A factor is a categorical variable; its first level is the reference in models.

# the start of every script
library(tidyverse)                         # load packages (install once, load every session)
ncd <- read_csv("data/ncd_survey.csv")     # path relative to the RStudio Project
glimpse(ncd)                               # rows, columns and the type of each column

Projects and scripts. Work inside an RStudio Project so paths like data/ncd_survey.csv work on any computer (no setwd()). Write everything in a script, never only in the console, and never overwrite the raw data.

Level 1 · Objects and types

ages <- c("45", "52", "38")
mean(ages)
#> [1] NA
#> Warning: argument is not numeric or logical: returning NA

Why does this fail?

  • A vector needs at least five values before mean() can work on it
  • One of the ages is missing, so the mean cannot be calculated
  • mean() works on data frames, so the vector has to be wrapped first
  • The ages are stored as text, so there is nothing to average
bp <- c(118, 126, 140, 132)
bp[2] + bp[4]

What does this print? (whole number)

res <- factor(c("Urban", "Rural", "Urban"))
levels(res)

Which level comes first, and so becomes the reference level in a model?

  • Urban, because it is the most frequent value in the vector
  • Neither; R treats the two levels as unordered with no reference
  • Urban, because it is the first value that appears in the data
  • Rural, because levels are sorted alphabetically by default

Level 2 · Projects and packages

Why is it worth opening your analysis as an RStudio Project rather than calling setwd() at the top of the script?

  • The project installs every package your script needs automatically
  • It stops other people from opening or changing your script
  • R runs noticeably faster when it is opened through a project file
  • Paths become relative to the project, so it runs on any computer

You installed dplyr last week. Today, in a fresh R session, filter(ncd, age > 50) gives: could not find function “filter”. What is the most likely cause?

  • The package is installed but has not been loaded in this session
  • The package was removed from your computer when R was closed
  • R needs the data to be sorted by age before it can be filtered
  • The function only works on files that were saved as Excel sheets

Put the start of a new analysis in a sensible order, from first to last:

  1. Read the data file into an object
  2. Save the script with a clear name
  3. Create an RStudio Project for the study
  4. Look at the structure: rows, columns and types
  5. Open a new script and load the packages at the top
  6. Put the raw data file in the project’s data folder

Boss · Review a first script

Boss: you are reviewing a colleague’s first script. Flag every line of advice that is wrong.

  • Putting setwd(“C:/Users/Asha/Desktop”) at the top makes the script run on any computer.
  • Loading the packages at the top of the script makes its requirements clear.
  • Saving the cleaned data over the original raw file keeps the folder tidy.
  • Comments that explain why a step is done help the next reader.
  • Typing commands only in the console is fine, because R keeps them for next time.
  • read_csv() returns a tibble, which prints just the first rows and the column types.
