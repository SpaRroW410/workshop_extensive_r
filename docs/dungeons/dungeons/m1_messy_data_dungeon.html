Region 2 · Messy Data Dungeon

Looking before changing; labels, types, duplicates, placeholders and a cleaning log

Briefing

Welcome to Region 2. Real data are messy, and every later result depends on how you clean them. Read first: Cleaning Messy Data. You need the file ncd_messy: every question that uses it has a download button.

The order of work. (1) Keep the raw file; clean a copy with a script. (2) Look: glimpse(), count() of each category, range() of each number. (3) Fix one problem at a time and re-check. (4) Keep a log of what changed and how many rows.

Types, placeholders, duplicates. parse_number() reads a number out of text such as “7.2 g” (check what still turns into NA). A code like 999 is a placeholder: set it to NA and report it, do not fill in a mean. distinct() removes exact copies; the same ID with different values needs a look at the source.

Level 1 · Look first

A colleague sends a field-survey spreadsheet. What should you do before you change anything in it?

  • Inspect types, ranges, labels and missing values; keep the raw file
  • Fix the obvious typos directly in the spreadsheet and save it again
  • Run the planned model first to see which variables cause the trouble
  • Delete every row that has a missing value so that the file is complete
count(d, sex)
#> sex      n
#> F       18
#> female  29
#> Female  91
#> M       22
#> Male    87
#> male    40

What is the best next step?

  • Keep the six labels, since each one is a different group of people
  • Drop the rows that are not spelled exactly as Female or as Male
  • Convert sex to numbers so that the spelling no longer matters at all
  • Recode the spellings into two labels, then count again to check
glimpse(d)
#> $ salt_g_day <chr> "7.2 g", "9.1", "8.4 g", "6.0", ...

Salt is stored as text because some entries carry a unit. What is the safest way to get a numeric column?

  • Convert with as.numeric() and accept whatever comes out of it
  • Round the column so that the units disappear from the text
  • Read the number out of the text, then check what failed
  • Delete the rows where the entry contains the letter g in it

Level 2 · Duplicates and placeholders

A cleaned survey file has 313 rows. Ten of them are exact copies of another row (every column the same). How many rows remain after distinct()? (whole number)

Three participants appear twice with the same ID but a different SBP and visit date. What is the best action?

  • Check the source forms: a repeat visit, a re-entry or a wrong ID?
  • Keep the first row of each ID and drop the second one without a check
  • Delete the participants completely, because their records conflict
  • Average the two SBP values and keep one single row for each person

In age, four entries are 999, which the codebook gives as ‘unknown’. What is the best treatment?

  • Set them to NA, and report how many there were
  • Delete the whole survey because the age data are unreliable
  • Replace them with the mean age of the other participants
  • Leave them, since a model can learn that 999 is special

Level 3 · Write the cleaning code

Task: ncd_messy has column names such as Pt ID and Age (yrs), and some rows are exact duplicates. Write code that gives the data with tidy column names and with the exact duplicate rows removed.

Task: after tidying the names with clean_names(), add a numeric column called age made from the text column age_yrs, using the function that reads the number out of text.

Boss · Audit a cleaning log

Boss: flag every flawed sentence in this cleaning log for a survey file (313 rows).

  • The raw file was left unchanged and all cleaning is done in a script.
  • Ten exact duplicate rows were removed with distinct().
  • Three participants with the same ID but different values were deleted without checking.
  • Age values of 999 were replaced by the mean age of the other participants.
  • SBP values of 0 and 1350 were set to NA and counted in the log.
  • Sex was recoded into two labels and a count confirmed no values were lost.
