Region 1 · Join Junction

Stacking rows, binding columns and joining tables by a key without losing or duplicating people

Briefing

Read first: Merging Datasets. Same columns, different people: stack rows with bind_rows(). Same people, different columns: join by a key such as id, never paste side by side with cbind().

patients <- tibble(id = 1:5, name = c("Asha", "Bina", "Chetan", "Dev", "Esha"))
scores   <- tibble(id = c(2, 3, 5, 6), score = c(85, 90, 88, 92))
inner_join(patients, scores, by = "id")   # ids in both
# A tibble: 3 × 3
     id name   score
  <dbl> <chr>  <dbl>
1     2 Bina      85
2     3 Chetan    90
3     5 Esha      88
left_join(patients, scores, by = "id")    # every patient; NA where no score
# A tibble: 5 × 3
     id name   score
  <dbl> <chr>  <dbl>
1     1 Asha      NA
2     2 Bina      85
3     3 Chetan    90
4     4 Dev       NA
5     5 Esha      88
full_join(patients, scores, by = "id")    # every id from either table
# A tibble: 6 × 3
     id name   score
  <dbl> <chr>  <dbl>
1     1 Asha      NA
2     2 Bina      85
3     3 Chetan    90
4     4 Dev       NA
5     5 Esha      88
6     6 <NA>      92

Check the key first. If an id appears twice in the right-hand table, a left join returns that person twice. Count rows before and after every join.

Level 1 · Stack or join?

Two survey rounds have exactly the same columns but different people. How should they be combined into one table?

  • Keep only the round that has the larger number of rows
  • Join them by id, keeping the people found in both
  • Stack them as rows, so each person stays one row
  • Put them side by side as extra columns of one table

After left_join(patients, scores, by = “id”), the score column is NA for ids 1 and 4. Why?

  • A left join always deletes the scores of the first rows
  • Those patients have no matching row in the scores table
  • Scores below a cut-off are converted to NA by the join
  • The ids 1 and 4 were stored as text in the patients table

A lab table and a survey table both have 600 rows, but the lab rows are sorted by sample date and the survey rows by id. What happens with cbind(survey, lab)?

  • R refuses because the two tables are sorted differently
  • The result has 1200 rows, one block for each table
  • Rows are pasted side by side, silently mixing up people
  • R matches the rows by id first, then pastes the columns

Level 2 · Count the rows

A patients table has ids 1, 2, 3, 4 and 5. A scores table has ids 2, 3, 5 and 6 (one row each). How many rows does inner_join(patients, scores, by = “id”) return? (whole number)

Same tables: patients has ids 1 to 5, scores has ids 2, 3, 5 and 6. How many rows does full_join(patients, scores, by = “id”) return? (whole number)

patients has 5 rows (ids 1 to 5). labs has rows for ids 3, 3 and 5 (id 3 was tested twice). How many rows does left_join(patients, labs, by = “id”) return? (whole number)

Boss · Audit a merge

Boss: flag every flawed sentence in this data-merging note.

  • An inner join kept only the 540 participants who had lab results.
  • A left join from participants to labs can never add rows.
  • cbind() is safe as long as both tables have the same number of rows.
  • Before joining, we checked that id was unique in the lab table.
  • After the full join, NA values show where one table had no matching row.
  • Joining by participant name instead of id is fine because names are unique.
