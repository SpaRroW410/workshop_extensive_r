Neighbours and Spatial Weights

Every spatial test in this track asks “are neighbouring areas more alike than chance?”. The word neighbour needs a definition first. That definition is the spatial weights matrix, and it is the most influential choice you make.

Contiguity neighbours

Two polygons are neighbours if they share a boundary:

  • Rook: share an edge.
  • Queen: share an edge or a corner (usual default).
nb_q <- poly2nb(blocks, queen = TRUE,  snap = 1e-4)
nb_r <- poly2nb(blocks, queen = FALSE, snap = 1e-4)
summary(nb_q)
Neighbour list object:
Number of regions: 79 
Number of nonzero links: 414 
Percentage nonzero weights: 6.633552 
Average number of links: 5.240506 
Link number distribution:

 1  7 13 20 28  9  1

3 with 2 links

24 with 8 links
c(queen_links = sum(card(nb_q)), rook_links = sum(card(nb_r)))
queen_links  rook_links 
        414         414 
cen <- st_coordinates(st_centroid(blocks))
plot(st_geometry(blocks), border = "grey70", main = "Queen contiguity: links between neighbouring blocks")
plot(nb_q, cen, add = TRUE, col = "red", pch = 19, cex = 0.4)

Check three things in the summary: the average number of neighbours (here about 5), the least and most connected areas, and any isolates (areas with no neighbours, which break many tests unless you use zero.policy = TRUE).

Distance-based and k-nearest neighbours

When areas are unequal in size, or are points, use distances between centroids:

knn5 <- knn2nb(knearneigh(cen, k = 5))                  # always exactly 5 neighbours
d <- unlist(nbdists(knn2nb(knearneigh(cen, k = 1)), cen))
nb_d <- dnearneigh(cen, 0, max(d))                      # everyone within the smallest distance that links all areas
par(mfrow = c(1, 2))
plot(st_geometry(blocks), border = "grey80", main = "5 nearest neighbours"); plot(knn5, cen, add = TRUE, col = "blue", pch = 19, cex = 0.3)
plot(st_geometry(blocks), border = "grey80", main = "Distance band"); plot(nb_d, cen, add = TRUE, col = "darkgreen", pch = 19, cex = 0.3)
Definition Neighbours per area Good for Watch out for
Queen / rook varies polygons of similar size islands (isolates); big areas have many neighbours
k nearest exactly k unequal areas, points links across a gap or border that are not real
Distance band varies points, catchment ideas too short leaves isolates; too long links everything

From neighbours to weights

A neighbour list says who; weights say how much. Styles in nb2listw():

  • "B" binary: 1 for every neighbour.
  • "W" row-standardised: each area’s weights sum to 1, so a neighbour’s influence is shared out. The usual choice.
  • "S" variance-stabilising.
lw <- nb2listw(nb_q, style = "W", zero.policy = TRUE)
lw$weights[[1]]           # the first block's weights: 1/(number of neighbours) each
[1] 0.25 0.25 0.25 0.25
sum(lw$weights[[1]])
[1] 1

The spatial lag

The spatial lag of a variable is the weighted average of the neighbours’ values. With row-standardised weights it is simply “the average of my neighbours”:

blocks$lag_rate <- lag.listw(lw, blocks$dengue_per_100k, zero.policy = TRUE)
blocks |> st_drop_geometry() |> select(block_id, dengue_per_100k, lag_rate) |> head(5) |>
  mutate(across(where(is.numeric), \(x) round(x, 1)))
  block_id dengue_per_100k lag_rate
1      B01            53.7     27.8
2      B02            31.0     44.9
3      B03            93.6     47.3
4      B04            30.5     35.7
5      B05            57.6     48.7
# check block 1 by hand:
mean(blocks$dengue_per_100k[nb_q[[1]]])
[1] 27.825
patchwork::wrap_plots(
  ggplot(blocks) + geom_sf(aes(fill = dengue_per_100k)) + scale_fill_viridis_c(option = "magma", direction = -1, name = "Rate") + labs(title = "Rate"),
  ggplot(blocks) + geom_sf(aes(fill = lag_rate)) + scale_fill_viridis_c(option = "magma", direction = -1, name = "Lag") + labs(title = "Spatial lag (neighbours' average)"))

The lag is smoother than the original. The Moran’s I statistic on the next page is essentially the slope of the lag against the value.

The choice matters

w_list <- list(queen = nb2listw(nb_q, style = "W", zero.policy = TRUE),
               rook  = nb2listw(nb_r, style = "W", zero.policy = TRUE),
               knn5  = nb2listw(knn5, style = "W"),
               distance = nb2listw(nb_d, style = "W"))
map_dfr(w_list, \(w) { m <- moran.test(blocks$dengue_per_100k, w, zero.policy = TRUE); tibble(I = unname(m$estimate[1]), p = m$p.value) }, .id = "weights") |>
  mutate(I = round(I, 3), p = signif(p, 2))
# A tibble: 4 × 3
  weights      I        p
  <chr>    <dbl>    <dbl>
1 queen    0.499 5   e-14
2 rook     0.499 5   e-14
3 knn5     0.511 1.80e-15
4 distance 0.543 1   e- 9

The conclusion is similar here because the clustering is strong, but with a weak pattern the answer can change with the weights. State your weights, justify them with the biology (how far does a mosquito or a person travel?) and check sensitivity.

Take-home

  • A weights matrix turns “near” into numbers; choose it deliberately (queen for polygons, k-nearest or distance for points).
  • Row-standardised weights make the spatial lag the average of neighbours.
  • Look for isolates and areas with very many neighbours; report your choice and test the sensitivity.
