Spatial Data with sf

This page introduces vector spatial data in R with the sf package, using a synthetic district of 79 blocks (data/gis/district_blocks.geojson) and 30 health facilities (data/gis/facilities.csv). The boundaries and numbers are invented; the district was built so that dengue incidence clusters in space, which the later pages exploit. gis/make_gis_data.R regenerates it.

What is spatial data?

Type Example In R
Points health facility, a case’s home sf (POINT)
Lines road, river sf (LINESTRING)
Polygons block, district, catchment area sf (POLYGON)
Raster population grid, satellite image terra / stars

An sf object is a data frame with one extra column, geometry. All the dplyr verbs you already know work on it.

Coordinate reference systems (CRS)

A CRS says how numbers become places. Two families matter:

  • Geographic (longitude/latitude, e.g. EPSG:4326, WGS 84): units are degrees. Good for storing and web maps, wrong for distances and areas.
  • Projected (metres, e.g. a UTM zone, EPSG:32644 for 78°E to 84°E in the northern hemisphere): good for area, length, distance and buffers.
st_crs(blocks)$input            # stored in longitude / latitude
[1] "WGS 84"
blocks_utm <- st_transform(blocks, 32644)
st_crs(blocks_utm)$input
[1] "EPSG:32644"
Warning

Always check the CRS before measuring. st_area() on degrees gives meaningless numbers. Transform to a projected CRS first. Two layers can only be combined when they share a CRS.

tibble(block = blocks_utm$block_id[1:3],
       area_km2_recorded = blocks_utm$area_km2[1:3],
       area_km2_computed = round(as.numeric(st_area(blocks_utm))[1:3] / 1e6, 1))

Joining attributes to polygons

A normal data join works, as long as you join onto the sf object (or sf keeps the geometry only on the left side):

extra <- tibble(district = c("North-West", "North-East", "South-West", "South-East"),
                officer = c("Dr Rao", "Dr Singh", "Dr Das", "Dr Khan"))
blocks |> left_join(extra, by = "district") |> st_drop_geometry() |> select(block_id, district, officer) |> head(4)
  block_id   district  officer
1      B01 North-East Dr Singh
2      B02 North-East Dr Singh
3      B03 North-East Dr Singh
4      B04 North-West   Dr Rao

Writing spatial data

st_write(blocks_utm, "blocks_utm.gpkg")      # GeoPackage: one file, any CRS, recommended
st_write(blocks, "blocks.geojson")           # GeoJSON: text, web friendly, longitude/latitude
st_write(blocks, "blocks.shp")               # Shapefile: still common; 10-character column names!

Take-home

  • An sf object is a data frame plus a geometry column; use st_read() and st_write().
  • Check st_crs() before every analysis; transform to a projected CRS (here EPSG:32644) to measure.
  • Joins on attributes use left_join(); joins on where things are use st_join() and st_intersects().
